Повторення Streamable HTTP

Навіщо повторюємо

Досі qauto MCP server працював через stdio: Cursor запускав процес і передавав credentials у env.

Перед міграцією освіжимо, що таке Streamable HTTP і чим він відрізняється від локального subprocess.

Повторення Streamable HTTP

Що це і навіщо

Transport layer визначає, як JSON-RPC доходить між Host і Server. Формат повідомлень той самий — змінюється лише доставка.

Streamable HTTP — мережевий transport: сервер як окремий процес з HTTP endpoint. Один процес — багато клієнтів. У stdio кожне зʼєднання — окремий subprocess.

Повторення Streamable HTTP

Ключові деталі

  • Client → Server: кожне JSON-RPC — HTTP POST на MCP endpoint
  • Server → Client: опційно HTTP GET (streaming)
  • Сесія: заголовок Mcp-Session-Id після initialize
  • Локально: сервер окремо, Host — лише по url

Повторення Streamable HTTP

stdio: command + env

Host сам стартує процес і інжектить credentials у env:

{
  "mcpServers": {
    "qauto-course": {
      "command": "uv",
      "args": ["run", "main.py"],
      "env": {
        "QAUTO_EMAIL": "user@example.com",
        "QAUTO_PASSWORD": "YourPass1"
      }
    }
  }
}

Повторення Streamable HTTP

HTTP: url + headers

Host не запускає subprocess — ті самі ключі йдуть у headers:

{
  "mcpServers": {
    "qauto-course": {
      "url": "http://127.0.0.1:8000/mcp",
      "headers": {
        "QAUTO_EMAIL": "user@example.com",
        "QAUTO_PASSWORD": "YourPass1"
      }
    }
  }
}

Повторення Streamable HTTP

stdio vs Streamable HTTP

  • Desktop / локально без окремого процесу → stdio
  • Окремий процес, Inspector, кілька клієнтів → Streamable HTTP
  • Production remote → Streamable HTTP + auth

Повторення Streamable HTTP

Місток до міграції qauto

У stdio секрети йшли через env у mcp.json — Cursor інжектив їх у процес сервера.

У HTTP режимі Cursor не стартує процес, тому блок env не працює. Далі — куди переїжджають credentials і де налаштовувати host / port.

Фінал заняття

Підсумки

На цій лекції ми освіжили Streamable HTTP, перевели qauto MCP server зі stdio на мережевий transport і розібрали, як credentials переїжджають з env у headers клієнтського конфігу.

Також розвели два рівні логування: log_level FastMCP (transport) і logging додатку (tools + httpx до QAuto) з маскуванням секретів.

Ключова ідея: host, port і streamable_http_path — у конструкторі FastMCP; у run() лишається вибір transport. Далі — контейнеризація MCP server.
